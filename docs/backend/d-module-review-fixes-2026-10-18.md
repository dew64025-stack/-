## 本次补充修复

| 问题 | 原因与影响 | 修复 |
| --- | --- | --- |
| 会话并发重试失败 | 授权等查询已建立 MySQL REPEATABLE READ 旧快照；发现唯一键冲突后，成员检查仍读旧快照，重复 INSERT 成员；会话详情也可能读不到胜出事务的行 | 沿用已有 `participant_key`，会话和成员使用 upsert；胜出会话及返回详情用当前锁定读取 |

| 旧版混合私聊仍可访问 | V25 已隔离新咨询者，但旧版多人共用的会话仍保留成员，原成员还能读取此前混在一起的私聊 | V27 保留原始消息及成员，用 `access_revoked_at` 隔离不符合双人成员约束的旧咨询/借用会话；列表、详情、消息读写、已读、未读总数统一拒绝访问 |
| 删除团队后仍能读取会话 | 原过滤只查 `team_members`，未检查团队本身是否已删除 | 会话访问同时校验团队校区、删除状态及当前成员/队长身份 |
| 部署目标版本不一致 | 数据库说明顶部仍写 V19，正文写 V25，最新代码已有 V26 | 统一到 V27，补充备份、停写、迁移、授权、回滚及隔离会话处理说明 |

## 部署注意

先备份并停止旧服务写入，再迁移至 V27、按 `DATABASE.md` 补齐已有 V25 过程的授权，最后启动新版本。只更新 jar 会因缺少列而失败。旧代码没有隔离检查，不能直接恢复旧消息入口；已隔离记录应由管理员核对，不能直接清空隔离时间。

本次 MySQL 操作仅针对任务专属容器的独立合成测试库，没有连接或修改现有业务库。真实微信、生产 Redis/S3、真实 DeepSeek、WebSocket 握手及学校同步适配器仍不属于本次验收；学校同步预留接口不能算作真实数据同步已完成。
