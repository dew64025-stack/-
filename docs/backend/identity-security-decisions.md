# 身份与权限实现补充决定

本文件将规划书和API第4/16节的实施边界明确化，不代表接口已实现。

## 学生身份

用户已确认学校认证接口暂时预留、当前保留人工复核。学号名单命中只提供复核线索，不直接授予studentVerified。verified只能来自有权限的本校审核员或将来受信任学校认证提供器，不能来自客户端字段。学校协议未提供前，不开放猜测的认证回调或“任意学号认证成功”开关。

身份流程为：真实微信换码 → 用户主动换取真实手机号 → 加密学号申请 → 名单辅助匹配 → 人工approve/reject。未知名单同样进入待审，而不是错误宣称不存在或自动通过。拒绝后允许重新申请；只允许一个有效pending/verified认证，每个学号同校最多一个verified归属。待审请求不占用别人永久学号，防恶意抢占。

## 会话与角色

学生Bearer与管理员Bearer/刷新Cookie分别使用namespace。管理员必须密码与MFA，不因为学生令牌里的同名角色就能访问管理接口。请求中的userId、openid、campusId、roles不会创建身份。

每次验证不透明accessToken后，读取现存用户/校园/手机号/认证/角色状态。禁用账号、删除账号、撤权即时生效。student角色不是认证证据，必须同时有已验证手机号和verified学生认证。

## 管理员与校园

管理账号使用独立密码哈希和加密MFA种子；受控CLI初始化，不提供公开注册管理员。管理员实际关联users和user_roles以沿用校园/审计外键。bootstrap不能生成固定通用密码、不能把MFA种子打印到普通日志。校级账号只管理本校；平台级跨校请求必须显式确定校园并留审计。安全调查不因为拥有campus_admin/platform_admin就自动授权。

## 新增迁移

V1～V6保持已发布内容不变；运行时协调从V7开始、身份补模型从V8开始。增加约束前要检测旧数据中的多个有效认证、重复手机号；迁移遇到无法判定的归属冲突就失败并要求受控修复，不自动删历史数据、不repair。保留已有数据库备份和原迁移记录。

## 真实集成与测试

微信适配器采用固定可信HTTPS域名与超时；生产不接收任意openid。测试替身仅在src/test出现。学校接口将来需要协议、学校授权、可信身份绑定与防重放设计；未接入不等于已经认证。H2行为测试、模拟HTTP/Redis adapter测试和真实服务联调在报告中分别列出，不混称通过。
