# 材智通校园平台 · 微信小程序前端开发与部署文档（修订版）

> 修订日期：2026-10-15。  
>  对照仓库：[dew64025-stack/-](https://github.com/dew64025-stack/-)。  
>  本次核验的远端默认分支：`main`；提交：`68fc6ab55160de0b6dec3c38ffc7b33d0a9695e9`。  
>  适用范围：原生微信小程序前端的建项、原型落地、接口对接、调试和发布准备。不是“仓库已经可以直接部署”的证明。

## 一、先说明当前能做什么

本次直接核验了 GitHub 默认分支的目录和提交。远端当前包含规划书、后端接口设计、数据库说明、SQL 和演示种子，**没有`miniprogram/`、`project.config.json`、前端 `package.json` 或已发布后端工程**。

因此现在可以依据契约创建前端、制作原型和使用本地 Mock 开发；不能克隆仓库后直接运行小程序，也不能认为接口示例地址已经存在。

本机另有尚未推送的后端开发分支。它与上述远端快照不同，且未完成全量验收；部分本地测试通过不等于 GitHub 上已有完整后端。真实联调前应由前后端双方确认服务提交、启动方式、可用路由和测试账号，不能只看接口文档中的历史“尚无运行实现”字样推断本机进度。

### 1.1 对照依据

按下列文件落实业务，不用 UI 生成工具的建议覆盖它们：

  1. [项目规划书](https://github.com/dew64025-stack/-/blob/68fc6ab55160de0b6dec3c38ffc7b33d0a9695e9/2026-10-13-campus-one-stop-platform-design.md)：五个入口、业务边界、技术方案、隐私和验收要求。
  2. [后端接口 v1.1](https://github.com/dew64025-stack/-/blob/68fc6ab55160de0b6dec3c38ffc7b33d0a9695e9/campus-backend-api-v1.1-reviewed.md)：方法、路由、输入、权限和返回结构。文档列的是计划接口，不是当前可用服务清单。
  3. [数据字典](https://github.com/dew64025-stack/-/blob/68fc6ab55160de0b6dec3c38ffc7b33d0a9695e9/DATA_DICTIONARY.md)及[数据库说明](https://github.com/dew64025-stack/-/blob/68fc6ab55160de0b6dec3c38ffc7b33d0a9695e9/DATABASE.md)：字段、状态和数据安全边界。前端不直接连接 MySQL。



若后续服务实现与契约不一致，先登记差异并同步接口文档，不自行猜字段、修改状态含义或把空返回当作完成。

## 二、技术选型与职责

项目 | 本项目采用的做法  
---|---  
小程序 | **微信原生小程序 + TypeScript** ，与规划书第 6.1 节一致  
页面 | WXML、WXSS、页面 JSON、TypeScript；不是直接运行 HTML 页面  
管理后台 | 独立 Vue 3 + TypeScript 工程；不把管理员登录、名单导入和审核权限放进学生端  
后端调用 | `wx.request`、`wx.uploadFile`、`wx.downloadFile`、`wx.connectSocket`，统一封装  
UI 原型 | 可选 Google Stitch，或使用其他设计工具；只作为设计参考，不作为业务实现或安全校验  
模型 | 用户已选择 DeepSeek，由后端接入；小程序不直接调用模型服务、不保存模型密钥  
数据库与文件 | 只由后端访问 MySQL、Redis、私密对象存储和扫描服务  
  
不要混用“原生 TypeScript 工程”和“UniApp/Vue 模板再转译”两条路线。若以后确实要换框架，需另行评估并调整构建、组件、测试和交付规范；本文件不把换框架作为落地步骤。

原生小程序运行在微信中，覆盖 iOS/Android 微信客户端；不是另外制作两个独立安装包。

## 三、创建可导入的工程

以下为**拟创建结构** ，不是当前远端已有文件。先用微信开发者工具创建原生 TypeScript 基础项目，再按照实际生成的模板调整。
```
 
    仓库根目录/
    ├── project.config.json          # 开发者工具项目配置
    ├── project.private.config.json  # 本机个性配置，不提交敏感内容
    ├── tsconfig.json                # 按官方TypeScript模板保留
    ├── package.json                 # 仅模板/实际依赖需要时存在
    ├── design/                      # 原型、截图、DESIGN.md；不放进小程序源码根目录
    └── miniprogram/
        ├── app.ts
        ├── app.json
        ├── app.wxss
        ├── sitemap.json
        ├── config/
        │   └── env.ts
        ├── types/                   # DTO、业务枚举、页面状态
        ├── utils/
        │   ├── request.ts           # 统一响应、错误、幂等、有限重试
        │   ├── auth.ts              # 学生端会话及单通道刷新
        │   ├── upload.ts            # Upload凭据和扫描状态
        │   └── datetime.ts          # 带时区时间与校园日期展示
        ├── api/
        │   ├── auth.ts
        │   ├── home.ts
        │   ├── opportunity.ts
        │   ├── material.ts
        │   ├── service.ts
        │   ├── mutualAid.ts
        │   ├── team.ts
        │   ├── community.ts
        │   ├── messaging.ts
        │   └── me.ts
        ├── mocks/                   # 仅开发构建使用；正式构建排除
        ├── components/
        ├── assets/tabbar/           # 本地Tab图标
        ├── pages/                   # 五个Tab，保持主包轻量
        │   ├── home/index.*
        │   ├── opportunity/index.*
        │   ├── service/index.*
        │   ├── mutual/index.*
        │   └── me/index.*
        └── packages/                # 分包，不是pages/sub这个目录名本身就能分包
            ├── opportunity/
            ├── material/
            ├── service/
            ├── mutual/
            ├── community/
            ├── messaging/
            └── account/
    

```

`index.*` 表示对应的 `.ts`、`.json`、`.wxml`、`.wxss` 文件。页面目录存在不等于已注册；新增页面必须同步实际 `app.json`。不需要空分包时可以暂不注册，不能注册不存在的页面。

### 3.1 开发者工具导入

  1. 选择真实的小程序项目，不选择小游戏；创建/启用 TypeScript 模板。
  2. AppID 使用本项目的 `wx019bf0b6d1a50ad3`，并确认开发人员已在该小程序后台获得权限。AppID 不是 AppSecret。
  3. 导入根目录；`project.config.json` 中核对 `compileType: "miniprogram"` 与 `miniprogramRoot: "miniprogram/"`。
  4. 保留当前模板生成的 TypeScript 编译设置；不复制其他版本工具的整份配置覆盖本项目。
  5. 注册五个 Tab 页和实际已创建的分包页面，补齐真实本地图标路径。
  6. 若模板确有 `package.json`，按该文件及锁文件安装依赖；没有文件或脚本时不要直接执行 `npm run dev/build`。原生开发者工具编译不等于 Vite 启动。



### 3.2 五个一级入口

`app.json` 中注册首页、机会、服务、互助、我的五个主包页面并配置五项 `tabBar`。分包用 `subPackages` 显式注册；共享组件和跨包依赖按微信规则组织。

Tab 页面切换使用 `wx.switchTab`，详情等非 Tab 页面使用相应页面导航；详情参数只传 ID 等必要数据，不传令牌、完整材料、手机号或学号。

主包、单分包、总包体积及资源限制，使用本次发布所用开发者工具和微信平台规则检查；本文件不写死可能变化的配额。大型截图、HTML 原型、设计源文件、视频和样例材料不进入代码包。

## 四、设计稿落地与五入口业务

### 4.1 设计工作流

  1. 先生成五个一级页和少量关键二级页，确认信息结构，再扩展详情、表单和异常状态。
  2. 将配色、字阶、间距、圆角及交互状态整理进 `design/DESIGN.md`，版本随设计变化记录。
  3. 工具能导出什么，就将对应设计产物放到 `design/`。不承诺 Stitch 的固定屏数、导出文件名或特定按钮功能；以使用时的工具版本为准。
  4. 原型转换为实际 WXML/WXSS/TypeScript；HTML、CSS、DOM 事件和浏览器库不能直接照搬。
  5. 用真实 DTO 和状态驱动页面，再做小屏、长文本、字体缩放、键盘、安全区及真机检查。`rpx` 是适配单位，不代表文字全部固定缩放；兼顾阅读和无障碍。



设计工具只接收脱敏/虚构示例，不上传学生材料、真实聊天记录、密钥或生产配置。

### 4.2 页面与接口映射

下表均为契约映射，是否可真实调用须以当次后端可用清单为准。

一级入口 | 页面范围 | 主要契约接口  
---|---|---  
首页 | AI助手、截止事项、推荐、热点、附近、搜索 | `GET /home/overview`、`GET /search`、`POST /ai/assistant/messages`、`GET /jobs/{jobId}`  
机会 | 五类机会、通知原文、资格建议、材料清单、收藏提醒、自行提交、竞赛组队 | `/opportunities`、`/favorites`、`/reminders`、`/checklists`、`/teams` 等对应具体路由  
服务 | 报修、投诉建议/问题广场、地图、拥堵、图书馆/教室预约、工单进度评价 | `/work-orders`、`/campus-issues`、`/crowd/observations`、`/resources`、`/reservations`  
互助 | 失物、二手、教材、技能、借用、组队、站内沟通、匿名关系与情感社区 | `/mutual-aid/posts`、借用/交接路由、`/team-applications`、`/conversations`、`/community/posts`  
我的 | 登录、手机号、学生认证、画像、成长、材料保险箱、发布/工单/预约历史、信用事件、授权和数据权利 | `/me`、`/me/profile`、`/student-verifications`、`/materials`、`/me/dashboard` 及第15节具体路由  
  
这里的复数前缀只是索引，**不能据此自行创造`POST /favorites` 等不存在的方法/路径**。以接口表里的完整方法、路径和参数为准。

### 4.3 不能被设计稿改变的业务含义

  * 游客能浏览开放校园的公开内容，不强迫所有页面先登录。
  * 登录、绑定手机号、学生认证是不同状态。需学生权限的业务在手机号已绑定、认证通过且账号可用后才开放；前端按钮状态不能替代后端检查。
  * 学校接口先预留，当前保留人工认证；学号填对或名单命中，不显示为自动认证成功。
  * 机会状态按数据库字典使用 `published/expired/archived` 等真实值，不另造 `ended`。未公开内容不能混进普通机会列表。
  * “报名”不代表平台代交。没有真实官方办理接口时展示原文、准备材料和“已自行提交”记录，不画出不存在的一键官方报名结果。
  * 资格是准备建议，显示“符合/可能符合/不符合”及理由；未知条件不能显示为确定符合。
  * 材料“通过基础检查/基本完整”不代表学校或主办方保证接受；单文件检查不等于整份机会清单齐全。
  * 信用展示具体事件、理由和纠错入口，不凭空做一个 AI 人格分。
  * “恋爱咨询”在本规划中落到匿名关系与情感社区及安全提示，不新增未定义的心理诊断或专业治疗能力。
  * 二手、借用只做撮合、沟通、交接与评价；没有付款、押金和退款模块，不展示相关功能。
  * 官方接口未接通时，明确显示演示预约/平台工单，不能承诺学校真实座位或官方处理结果。



## 五、环境与 Mock 隔离

将“连接哪个服务器”和“是否使用本地假数据”分开配置：

配置 | 用途  
---|---  
`apiEnv` | `local/test/prod`，选择已确认的后端地址  
`dataMode` | `mock/api`，明确选择本地演示或真实请求  
服务端 `sourceType` | `demo/manual/official`，业务来源，不等于小程序编译环境  
  
本机地址示例为 `http://127.0.0.1:8080/api/v1`，只适合同一电脑的工具调试。手机上的 `127.0.0.1` 指手机本身；真机需可达的受控测试网络或已配置的 HTTPS 测试域名，不把数据库或扫描端口暴露公网。

`https://demo-api.example.com/api/v1`、`https://api.example.com/api/v1` 都只是占位示例，未部署、不可直接使用。正式域名必须由运营方实际准备，不能把示例值复制成上线配置。

开发版、体验版、正式版可用 `wx.getAccountInfoSync().miniProgram.envVersion` 辅助选择预定义环境，但正式包不能通过任意本地开关、URL 参数或调试入口切入 Mock/任意域名。环境映射要经过发布检查。

Mock 必须：

  * 只在明确的开发/演示模式启用，页面持续显示“演示数据”。
  * 复用契约 DTO，覆盖加载、空列表、字段错误、权限不足、版本冲突、待扫描、扫描失败、审核中、任务失败等状态。
  * ID 也使用字符串，未知值使用 `null`，不能用随手编的字段掩盖缺口。
  * 断网、401、403、404、5xx、官方数据失败时，**不自动降级到 Mock** ；否则会把失败伪装成成功。
  * 不把 Mock 登录、假 clean 扫描或假认证带进正式代码包；演示身份不用于真实 API。



## 六、请求封装与错误处理

### 6.1 类型、请求头与响应

  * 所有 BIGINT ID/外键为十进制字符串；不要 `Number(id)`、`parseInt(id)`、一元加号或减法比较 ID。使用字符串相等，排序使用服务端顺序/游标。
  * 版本、计数、大小保持数字；布尔值保持 JSON 布尔；数组元素按契约类型，不发送字符串化的布尔或数字 ID。
  * 日期时间使用带时区 RFC3339；预约 `slotDate/startTime/endTime` 按校园当地日期和时间解释，不能把所有日期都转 UTC 后截字符串。
  * 金额是两位小数的十进制字符串。使用受控校验/十进制处理，不用浮点运算决定金额。
  * 只发送白名单字段；不要把页面 `setData` 状态整体发送，也不要发送客户端推断的角色、校园、审核结果或所有者。
  * JSON 请求按需带 `Content-Type: application/json`；已登录接口带 `Authorization: Bearer <accessToken>`。公开接口不强加登录凭据。
  * 业务写请求按契约带 `Idempotency-Key`；版本号同步 `X-Client-Version`。管理员认证不复用学生会话。



统一成功响应保留 `success/data/requestId/timestamp`；失败响应必须处理完整错误对象：
```
 
    {
      "success": false,
      "error": {
        "code": "VALIDATION_FAILED",
        "message": "请检查填写的信息",
        "fieldErrors": [
          { "field": "endTime", "code": "TIME_RANGE_INVALID", "message": "结束时间必须晚于开始时间" }
        ],
        "retryable": false
      },
      "requestId": "req_example",
      "timestamp": "2026-10-15T12:00:00+08:00"
    }

```

不能因为 `wx.request` 进入 `success` 回调就判业务成功；还需检查 HTTP 状态和响应结构。HTTP 201/202 也是合法成功，不只接受 200；202 表示任务受理，不是业务完成。网络错误和 HTTP 业务错误分别处理。

### 6.2 幂等键与版本

同一次用户业务意图生成一个键，防重复点击和网络重试时复用；不要每重试一次就生成新键。同键换正文会冲突，因此用户实质修改输入后视为新的操作。

不能笼统规定“所有 POST 都自动重试”。登录、refresh、手机号换码、二次认证、上传意向、临时签名/票据及二进制上传有各自凭据规则；具体例外以契约和后端可用清单为准。预约、发布、评价、注销等普通业务写不能省略幂等键。

带 `version` 的命令使用最近读取的正确对象版本；用户资料和画像的版本分开。409 冲突时刷新服务器数据、保留用户草稿并提示重新确认，不自动拿新版本重交旧表单。

### 6.3 分页与失败反馈

情况 | 前端处理  
---|---  
400/字段错误 | 显示对应字段；必填、格式、日期顺序等在输入/失焦时先提示，提交前再检查  
401 | 正常 Bearer 业务可触发一次受控刷新；凭据换码/Upload失败不能机械套同一重试逻辑  
403 | 展示缺少手机号、认证、权限或受限原因；不一律清空登录状态  
404 | 提示不存在或不可访问；不通过别的列表、校园参数或Mock绕过  
409 | 区分版本、幂等、业务状态冲突；按错误码恢复，不把失败当成功  
429 | 提示频率限制，有限退避，不形成请求风暴  
超时/5xx | 保留输入，展示安全提示；业务写结果不明时优先查询状态，确需重试则复用原幂等键  
  
普通列表使用 `cursor/limit`，默认20、最大100；地图另有最大200的边界。筛选、校园或排序条件变化时清空旧游标，不跨条件复用；读取 `hasMore/nextCursor`，不自己计算游标。关键字 `q` 为1～100字符。

记录用于排障的 `requestId`、错误码和必要路由，不记录完整请求头、令牌、手机号、学号、材料内容或完整签名URL。

## 七、微信登录、手机号与认证

### 7.1 学生登录和刷新

  1. 用户进入需登录功能时调用 `wx.login` 取得一次性 `code`。
  2. 发送 `POST /auth/wechat/login`，正文只按契约提交 `code` 和开放校园 `campusCode`。
  3. 保存学生端会话及有效期；access/refresh 是不透明令牌，不按 JWT 解析，也不从中读取权限。
  4. access 优先保留内存；如需登录持久化，仅在必要的本机存储保存最少会话信息，理解小程序本地存储不是秘密保险箱。退出、切换账号或刷新失败时清理令牌及用户私密缓存。
  5. **多个请求同时401只允许一个刷新请求** ，其他请求等待同一刷新结果；成功后同时替换新 access/refresh，按各自原幂等键重试一次。
  6. 刷新失败结束队列并进入重新登录，禁止无限递归刷新。不要反复复用已轮换的旧 refreshToken。
  7. 退出调用 `/auth/logout` 撤销会话，不只是清本地缓存；访问令牌过期但有有效刷新会话时，按接口约定注销。



客户端禁止保存 AppSecret、DeepSeek Key、数据库密码、对象存储密钥或自行提交 openid 冒充登录。源码中只有 AppID 不构成服务端鉴权。

### 7.2 手机号与学生认证

手机号由用户主动使用微信手机号授权能力取得一次性凭证，然后调用 `POST /auth/phone/bind`，正文为 `{phoneCode}`。登录 code 与手机号 code 不混用；不通过普通文本框传一个号码就宣称验证成功。当前 AppID 是否具备相应能力，需在后台确认。

认证申请为 `POST /student-verifications`，学号最多32字符；只显示后端确认的 unverified/pending/verified/rejected 等实际状态。拒绝后保留原因与重新申请入口，不把学号命中名单等同本人身份已核验。

昵称1～32字符；技能和兴趣每类最多20项、每项1～32字符；学院、年级使用本校允许值。头像只使用本人已扫描通过的附件，不提交任意网络地址。

拒绝非必要授权后仍可使用公开功能。定位只在用户主动使用附近时申请；拒绝后提供手动区域或 `nearbyMode=unavailable`，不伪造距离。

## 八、文件上传、材料与异步状态

### 8.1 上传步骤

  1. 选择文件后即时检查扩展类型、大小和基础命名，显示清晰错误；服务端仍会独立校验。
  2. 材料申请 `POST /materials/upload-intents`；头像等申请 `POST /files/upload-intents`，`purpose` 严格对应业务。学生端不能使用管理员名单/通知用途。
  3. 使用返回的 `uploadUrl`、`uploadId`、临时 `uploadToken` 调用 `wx.uploadFile`，multipart 字段名为 `file`，只上传一个文件；请求头为 `Authorization: Upload <uploadToken>`，不能替换为 Bearer。
  4. 不手动设置带错误 boundary 的 multipart Content-Type。`wx.uploadFile` 的响应 `data` 通常需解析为 JSON，解析失败、HTTP非成功均作为失败处理。
  5. 上传收到不代表可使用。用正常 Bearer 会话调用 `POST /files/uploads/{uploadId}/complete`，带业务幂等键，保存 `attachmentId/jobId/scanStatus`。
  6. 查询文件元信息或已实现的任务查询接口，在页面可见时有限轮询；离开页面暂停轮询，不因本地等待超时就擅自把后端任务标失败。
  7. 只有 `scanStatus=clean` 才能绑定材料/头像/业务附件、下载或送 AI；pending 显示处理中，infected/failed 明确阻止使用并说明重新上传或重试路径。
  8. 材料用 clean 附件调用 `POST /materials`；追加版本走 `/materials/{id}/versions`，不能覆盖被旧清单绑定的历史版本。



客户端校验限额：材料20MiB、业务图片5MiB、每个业务对象最多9张图片；允许 JPEG/PNG、PDF、DOCX，头像仅 JPEG/PNG。实际限制还应和服务器公开配置对齐。前端不负责判定无病毒，也不能自行将状态置 clean。

### 8.2 下载与预检

材料下载先申请 `/files/{attachmentId}/download-url`，私密签名有效期按契约为120秒。过期重新授权申请；不保存为永久地址，不写入日志，不把对象键当成URL。

生产下载涉及 API、签名对象存储或文件代理的实际域名，应按实际链路核对 HTTPS、合法域名和真机可达性。只配置 API 域名不足以保证另一个存储域名可下载；内网或回环存储地址也不能直接交给手机。

材料使用 AI 之前取得专门 `material_ai` 授权，明确目的、服务商和保存规则；没有授权不调用。清单预检结果展示 `passed/confirm/missing`、证据、`basicComplete` 和 `stale`，材料替换后旧结果保留但标过时。错误提前提示，不能等最后一步才一次性汇总。

## 九、消息、预约、审核与来源显示

### 9.1 消息

  * 首版发送消息走 REST，`clientMessageId` 最大64字符，同一发送重试保持不变；WebSocket用于事件接收和心跳。
  * 连接前调用 `POST /realtime/tickets` 获取30秒一次性 ticket 和 `websocketUrl`；只使用该受控 WSS 地址，不在URL放长期 access/refresh。
  * 按契约处理心跳、断线退避和前后台切换；重连后按消息游标补拉并去重，不能把推送当作唯一持久事实。
  * 用户退出、账号切换时关闭连接并清理旧会话数据。只处理本人有权访问的会话，不自行指定任意成员。
  * 订阅通知需微信侧真实授权和后端模板/次数校验；提交 `consentResult=accept` 不代表后台一定发送成功，不承诺应用退出后靠轮询持续提醒。



### 9.2 预约与内容状态

预约以服务器返回的 slot、容量、seatNo、版本和最新状态为准；按钮禁用不能代替并发防超卖。取消、签到需要对应前置状态；签到按短期凭证/正式授权方式进行，不把GPS坐标当作唯一签到依据。

报修数据库 completed 但未评价时，按 `serviceStage=awaiting_rating` 显示待评价，不直接显示整项已完成。帖子、问题、评论、证据等提交后按返回结果显示待审，不自行插入公开列表冒充发布成功。

匿名社区不能在普通DTO/页面/日志/埋点中携带真实作者ID、可串联跨帖身份或真实姓名；匿名内容不进入成长档案。保留举报、屏蔽、申诉及安全提示入口。

### 9.3 六个来源字段

资源、预约、通知、机会、工单、问题、拥堵、互助对象读取六个**顶层** 字段：`sourceType`、`sourceName`、`updatedAt`、`isStale`、`officialReference`、`externalId`。

不要实现为 `data.sourceFields.sourceType`。文档表格的 sourceFields 只是缩写。

`demo` 持续显示演示标识；`manual` 显示平台人工维护；`official` 仅按后端可信来源展示，前端不能改。过期信息提示可能不再实时，官方失败明确报错、不换假数据。AI内容显著标识辅助生成及来源；资料不足明确未知，不能补造学校政策。
